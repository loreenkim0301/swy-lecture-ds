# SELECTWAY 교안 작성 원칙

`swy-lecture-ds`는 CSS/JS 컴포넌트일 뿐, 강의 교안을 잘 쓰는 법까지 알려주진 않습니다.
이 문서는 SELECTWAY가 실제 교안([`swy-lecturenote`](https://github.com/loreenkim0301/swy-lecturenote))을 쓰면서 정리한 **글쓰기 원칙**이고, 원칙마다 이 라이브러리의 어떤 클래스로 구현하는지 짝지어 정리했습니다.

컴포넌트만 쓰고 싶다면 이 문서는 몰라도 됩니다 → [README의 "1) 컴포넌트만 쓰기"](../README.md#1-컴포넌트만-순수하게-쓰기) 참고.
교안 결과물의 완성도까지 높이고 싶다면 아래 6가지를 순서대로 적용하세요.

---

## 1. 목차와 제목을 반드시 연결한다

사이드바 목차(`.sw-sidebar nav`)의 링크 `href="#s1-2"`와 본문 제목의 `id="s1-2"`는 **항상 1:1로 일치**해야 합니다. 하나라도 어긋나면 클릭해도 안 움직이거나, 스크롤스파이(`sw-ds.js`)가 엉뚱한 항목을 하이라이트합니다.

```html
<!-- 사이드바 -->
<nav><ol><li><a href="#s1-2">1.2 기존 제품 개발 흐름</a></li></ol></nav>

<!-- 본문 -->
<h2 class="sw-sub-title" id="s1-2">1.2 기존 제품 개발 흐름</h2>
```

## 2. 넘버링은 대분류 1단계, 소분류 2단계로 고정한다

- 대분류(`.sw-section-title`, `<h1>`): `1.`, `2.`, `3.` — 목차의 최상위 `<li>`
- 소분류(`.sw-sub-title`, `<h2>`): `1.1`, `1.2`, `1.3` — 목차의 중첩 `<li><ol>`

3단계(`1.1.1`)까지 내려가면 목차가 너무 길어져 오히려 못 찾습니다. 소분류 안에서 더 쪼개야 하면 `<h3>`(넘버링 없이 소제목만)를 쓰세요.

```html
<nav>
  <ol>
    <li><a href="#s1">1. 기획자의 제품 개발 흐름</a>
      <ol>
        <li><a href="#s1-1">1.1 기존 제품 개발 흐름</a></li>
        <li><a href="#s1-2">1.2 AI 이후 초기 기획 단계</a></li>
      </ol>
    </li>
  </ol>
</nav>
```

## 3. "제목 → 설명(서술형) → 보충자료" 순서를 지킨다

제목 바로 아래에 표나 프롬프트 박스부터 넣지 마세요. **먼저 이 섹션에서 무엇을, 왜 하는지 한두 문단 서술**로 설명하고, 그다음에 단계·이미지·표로 구체화합니다.

```html
<h2 class="sw-sub-title" id="s3-5">3.5 문제정의부터 기획서 약식</h2>
<p>여기서는 막연한 아이디어를 실제로 만들 수 있는 문제 정의 문장으로 좁히는 방법을 다룹니다. 타깃, 현상, 문제 세 가지로 나눠보면 훨씬 구체적인 문장이 나옵니다.</p>
<!-- 서술이 끝난 다음에 표/단계/프롬프트가 옴 -->
<div class="sw-tablewrap">...</div>
```

**나쁜 예**: 제목 → 바로 표 → (설명 없음). 읽는 사람이 "이게 왜 필요한지" 모른 채 표부터 봅니다.

## 4. 이미지·표는 출처와 주석을 명확히 표시한다

`.sw-cite`를 섹션 끝에 붙여서 근거·출처를 작게 표시합니다. 데이터를 인용했다면 반드시 이 블록으로 밝히세요.

```html
<div class="sw-cite">
  <span class="sw-cite-label">출처</span>
  Nielsen Norman Group, "Why You Only Need to Test with 5 Users" (2000)
</div>
```

## 5. 이미지는 발췌보다 직접 제작한다

외부에서 스크린샷을 그대로 긁어오면 저작권 문제와 브랜드 톤 불일치가 생깁니다. 가능하면:
- 직접 캡처한 프로토타입 화면
- 자체 제작한 SVG/PNG 목업 (`.sw-modal`, `.sw-card` 같은 컴포넌트로 화면 안에서 직접 구성)
- 부득이 외부 이미지를 쓸 땐 반드시 `.sw-cite`로 출처 표시

## 6. 톤앤매너: 친근하고 쉽게, 존댓말, 예시 중심

- 전문 용어를 쓰기 전에 일상 비유로 먼저 설명 ("배포와 출시는 달라요" 식)
- 문장은 짧게, 존댓말 유지
- 추상적 설명 뒤에는 항상 구체적 예시나 실습 프롬프트를 붙임

---

## 체크리스트

새 섹션을 쓸 때마다 이 순서를 확인하세요.

- [ ] 목차 `href`와 본문 `id`가 정확히 일치하는가
- [ ] 넘버링이 대분류/소분류 2단계 규칙을 따르는가
- [ ] 제목 다음이 표/이미지가 아니라 서술형 설명인가
- [ ] 인용한 이미지·표에 `.sw-cite`로 출처를 달았는가
- [ ] 이미지를 직접 만들었는가 (또는 출처를 밝혔는가)
- [ ] 존댓말·쉬운 언어·구체적 예시로 썼는가
